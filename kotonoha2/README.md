# Kotonoha Project 视觉小说制作规范

本项目将用户提供的《言ノ葉プロジェクト》小说及素材整理为 WebGAL 视觉小说。本文是当前制作、修复与验收的项目约定。未经用户确认，不得自行改变已验收的表现方式。

## 1. 基准与当前范围

- 第二章制作范围为 Chapter 2-1～2-6。用户提供的六节原文共 1,819 个文字段落、18 张剧情插图。
- 以 GitHub 仓库 Haisairova-Official/haisairova.akiacg.com 的已验收 kotonoha2 为基准，已核对提交：ecdda75cf76c6ca9bed11b720131828bbcc8f092。
- 已验收第一章覆盖 1-1～1-7。仅含 1-1 的旧 r10 本地备份不得替代最新基准。
- 直接沿用第一章的脚本写法、引擎、界面、人物参数与已验证修复。第二章主要替换台词、场景素材及音频节点。
- 不另做一套布局，不重新发明人物缩放机制，不以“资源引用通过”代替视觉验收。
- 当前工程仍在制作和修复中，不能因译文齐全就宣称成品完成。

## 3. 文本与译名

### 3.1 翻译规则

- 完整处理用户提供的原文，保留原段落 ID 与中日对应关系。
- 不用摘要替代正文，不漏段，不编造原文没有的剧情或台词。
- 标注说话人；身份推断需结合上下文、关系图和图片，有疑问向用户确认。
- 情绪、演出备注、来源及推测可保存在制作文件中，不得混进玩家看到的正文。
- 游戏内不得出现“原作插图”、制作说明、调试注释或占位提示。
- 保留剧情中的身份揭示顺序，不能提前剧透伪装者。

### 3.2 名字锁定

第一章已出现人物的名字全部沿用已验收文本，不得擅自重新翻译。包括但不限于：
阿乌尔、莉茨、休特·鲁、克莱门斯、艾莉、马斯提马、拉尔夫、特里斯坦。

- 已验收的“没想到她就是那个容器”及“容器”上方 Flask 注音保留，不回退为“烧瓶”。

## 4. 素材优先级与背景

按以下顺序选择素材：
1. 当前章节已有官方图、用户提供素材。
2. 之前章节已有 CG、背景、立绘及其他适用素材。
3. 基于上述原图修改、扩图、去除人物或制作必要差分。
4. 确实缺少时，依据现有图片和原文推断并生成补充素材。

用户明确允许复用或修改之前章节的 CG 等素材。复用必须符合场景、时间、人物状态与剧情，不得只为填空使用无关背景。

- 补绘必须统一官方图的画风、建筑设计、材质、时代与配色。
- 背景生成必须严格按照小说内容，必要时参考视频与网页所含图片。每个需补绘背景先记录章节、原段落 ID、原文明确描述及对应网页 CG／视频参考；未写明的细节仅可保守补全，不得与原文冲突。所有候选图（包括夜间包厢）须先核对，时间、窗户结构或陈设冲突时必须重做，未经核对不得采用。
- 需要高清化时优先保留原图特征，避免把细节改成另一套设计。
- 原文明确的时间、光照、门窗结构、室内装饰必须遵守。
- 侦探事务所的维多利亚式墙纸与陈设不能忘记；酒吧门的单双开结构以原图为准。
- 严禁用粗糙几何色块、程序生成示意图或占位 SVG 冒充正式背景。
- 新补绘中原图不可见部分应在制作记录中注明推定，但不在游戏正文展示注释。
- 已被拒绝的 c2_cabin.svg、c2_suite.svg、c2_corridor.svg、c2_dining.svg、c2_fire.svg、c2_station.svg、c2_manor.svg、c2_carriage_day.svg 不得重新作为正式背景引用。

## 5. 立绘与人物表现

### 5.1 原图与裁切

- 逐张查看素材确认身份与服装，不能只凭文件名。
- 设定图可能同时含正面、背面及留白，必须选出正确人物部分。
- 以人物实际可见边界校准大小，不按整张图片画布统一缩放。
- 不误切头发、手、裙子、腿或服饰；不得残留背面人物、底板、硬直矩形边。
- 旧角色优先直接复用第一章已验收的立绘、裁切及参数。
- 米歇尔使用用户暂定认可的补绘版；未知下半身细节属于补绘，不冒充原作完整设定。
- 约翰尼缺少可靠外貌线索时使用剪影或不露脸构图，不擅自造出确定长相。
- 未具名路人采用“路人A／B”等适当名称及整体剪影，不做黑头和彩色身体拼接。

### 5.2 场景人物

- 延续第一章已验收的构图及比例：底部留适量腿部，头顶有空间，不顶天、不缩成小人。
- 头部高度以已验收画面为视觉基准，不能机械套用单一百分比。
- 多人出现时应同框，并按角色实际身高合理安排；不得因源图尺寸不同造成比例失调。
- 保持人物间距，避免无剧情依据的重叠或穿插。
- 有动作的段落应有适量对应演出，不让整章人物完全静止。
- 常服、制服伪装、恶魔形态等状态必须与当前剧情一致。

### 5.3 当前说话人头像

- 沿用第一章：说话人的半身头像位于左侧、对话框体下方图层，头部从框外露出。
- 下缘保留渐隐／虚化，不能出现明显硬切口。
- 使用半身构图，不把整个人缩进头像区。
- 头像与场景立绘独立控制；切换说话人时不能误改变场景人物尺度。

## 6. 对话框、字体与交互

- 保持第一章已验收界面，不新增第二层大矩形背景。
- 已读文字浅蓝，未读文字白色，颜色不得在迭代时回退。
- 字号与行距必须适配实际文字长度；桌面和移动端均不遮字、不溢出。
- 对话框、姓名、头像、按钮层级协调，不能互相盖住。
- 保留已有回想、自动、快进、存读档和全屏行为。
- 不把测试按钮或开发信息放进成品界面。
- 场景切换使用适当黑场或淡入淡出，避免突然跳切；不为每句话滥加转场。

## 7. 音频与章节顺序

- BGM 不能全程持续播放，只在关键或适合氛围的段落进入，并合理淡入淡出。
- 第一章原有 A／B 使用逻辑与已验收修复不回退：事务所用 A，回忆拍卖及战斗在合适位置使用 B。
- 本集新增素材：音视频素材/BGM/第二季/C.wav；时长约 190.663 秒。
- 本集 ED：音视频素材/VIDEO/第二季ed.mp4；时长约 194.510 秒。
- 第二章固定顺序：2-5 结束 → ED → 2-6。
- ED 正常播放完成或用户跳过都必须正确进入 2-6，不重复播放、不丢失进度。
- 第一章 OP 仍在 1-1 结束后，不能因第二章接入而改变。
- 添加符合情境的环境音和动作音效。使用有明确许可的免费／免版税资源，并记录来源和许可；“免费下载”不等于无版权。
- 移动端音频须在用户交互后正常解锁；不能卡在“正在测试声音”，不能静默吞掉播放失败。
- 实测 BGM、音效、ED 的播放、暂停、跳过、存读档恢复和跨章节衔接，避免同时叠播或音量失衡。

## 8. 按章节预加载

- 每次加载当前章节所需资源，而非首次加载全部章节。
- 资源清单包含实际使用的立绘、背景、CG、音乐和音效；视频采用可验证、不会长时间阻塞的加载策略。
- 显示真实加载进度，失败时可重试，不无限等待。
- 弱网下不得先推进剧情再等待关键图片出现。
- 进入下一章时按该章清单加载；缓存可复用资源，避免不必要重复下载。
- 检查路径、大小写、MIME 类型及播放格式，不能只验证文件存在。

## 9. 结束画面

- 黑屏保存界面承担“未完待续”作用，只出现在当前制作内容的最终末尾。
- 本次完整制作至 2-6，结束画面应在 2-6 后。
- 不在 2-5 的 ED 前后错误提前终止，也不在普通章节切换中弹出最终结束画面。

## 10. 必须通过的验收

### 内容与资源
- 六节中文正文与 1,819 个源段落逐条对应，无缺失、重复或多余 ID。
- 原文、译文、说话人、立绘身份和状态一致。
- 所有引用资源存在且可以加载，不能有被拒绝背景或未披露占位素材。
- 第一章原有内容与已验收修复不退步。

### 视觉
- 对照第一章，在相同画布比例下检查单人、双人、多人同框。
- 必测阿乌尔＋艾莉、阿乌尔＋克莱门斯以及各新增人物。
- 逐人检查裁切、头顶留白、身高、底部位置、头像半身构图和渐隐。
- 只有一层对话框；已读／未读颜色正确，长句不遮挡。
- 背景画风和剧情一致，不能用结构检查代替截图检查。

### 行为与音频
- 逐节进入、保存、读取、快进及自动播放正常。
- 章节预加载进度、失败重试和弱网表现可验证。
- ED 完整播放与跳过两条路径均进入 2-6。
- 音频与人物动作正常；结束画面只在 2-6 后。
- 桌面及移动尺寸完成浏览器回归，并明确哪些实机尚未测试。

## 11. 交付与进展说明

- 交付实际可运行的本地版本，提供经过验证的启动方式、访问地址、版本和测试结果。
- 如需私人外网试玩，另行确认交付方式与访问范围，不擅自公开部署。
- 汇报区分“翻译完成”“脚本生成”“可运行”“视觉通过”“最终验收”，不混为一谈。
- 有卡点要具体说明；有明显视觉缺陷时继续修，不以“成品”命名掩盖问题。
- 用户最新反馈优先。任何对第一章已验收效果的改变，都须有明确理由及用户授权。
